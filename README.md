# Coherence — подмена идентичности устройства

## Если коротко

Запусти на телефоне одну команду:

```sh
su -c 'sh fix-privacy.sh'
```

Она сама починит настройку экрана и откроет нужный экран настроек.
Там нажми **«Удалить рекламный идентификатор»** — это самое важное.

Всё остальное ниже — подробности, читать необязательно.

---

Magisk-модуль для Tecno Spark Go 1 (`TECNO KL4`, Unisoc T615, Android 14 Go).
Применяет профиль идентичности **только если профиль остаётся согласованным
с железом, которое у телефона есть на самом деле.**

Начни с этого раздела, а не с установки.

---

## Сколько это на самом деле даёт

Коротко: **подмена `Build.*` — косметика.** 2–4 бита из примерно 32,
нужных, чтобы выделить один телефон из ~3.5 млрд.

Рекламный идентификатор (GAID) даёт **32 бита сам по себе**. И SDK, которые
читают `Build.MODEL`, отправляют его **в том же сетевом пакете**, что и GAID.
Менять поле, едущее рядом с неизменным первичным ключом, не разрывает связку
ни в одном месте.

Порядок действий по убыванию отдачи:

| | Что | Отдача |
|---|---|---|
| 1 | Удалить рекламный ID | **высокая** — ~32 бита, работает во всех приложениях |
| 2 | Сбросить override экрана | **высокая** — бесплатно, см. ниже |
| 3 | Рандомизировать SSAID | **высокая** — переживает переустановку приложения |
| 4 | Гигиена сети и разрешений | **высокая** — IP с 2025 года разрешён рекламодателям явно |
| 5 | Проверить набор модулей Magisk | средняя — чужие модули светят редкие `debug.*` |
| 6 | Подмена `Build.*` | **низкая** — 2–4 бита |
| — | Ротация профиля по расписанию | **вредна** |
| — | Профиль флагмана (Pixel, Galaxy S) | **вредна** |

Первые четыре пункта — `tools/privacy-actions.sh`. Модуль — шестой пункт.
Если сделать только одно, делай первое, а не шестое.

## Чего этот модуль скрыть не может

Подмена свойств прячет **имя** устройства, а не устройство. Эти каналы
читаются любым приложением **без единого разрешения**, и `resetprop` не
достаёт ни до одного:

| Канал | Что покажет |
|---|---|
| `GL_RENDERER` (OpenGL ES) | `Mali-G57` — настоящий GPU |
| `VkPhysicalDeviceProperties.deviceName` | то же самое через Vulkan |
| `/proc/cpuinfo` | 8 ядер, 2×Cortex-A75 + 6×Cortex-A55 |
| `/sys/devices/system/cpu/**/cpufreq` | таблица частот Unisoc, потолок 1.8 ГГц |
| `/proc/meminfo` MemTotal | 2 855 468 kB — прямо из ядра |
| `ActivityManager.isLowRamDevice()` | `true` — класс Android Go |
| `MediaCodecList` | имена кодеков `c2.sprd.*` — вендор чипа открытым текстом |
| `Display.getMode()` | физические 720×1600, override не применяется |
| `Build.HARDWARE` | `ums9230_KL4_go` — и плата KL4, и конфигурация Go |
| `/system/build.prop` как файл | исходное `ums9230_KL4_go-user 14 …` |
| `SensorManager.getSensorList()` | вендорные строки датчиков |
| ~900 свойств `ro.os_*`, `ro.itel_style.*` | Transsion HiOS |

Два пункта стоит пояснить.

**`ro.hardware` менять нельзя.** По нему `init` импортирует `init.$X.rc`, а
`libhardware` ищет HAL-библиотеки (`camera.$X.so`, `sensors.$X.so`). Подмена
даёт телефон без камеры и датчиков либо bootloop. Вдобавок значение приходит
из `androidboot.hardware` в командной строке ядра и запись всё равно не
пережила бы перезагрузку. Значит `Build.HARDWARE` выдаёт настоящую плату при
любом профиле.

**`/system/build.prop` остаётся прежним.** `resetprop` переписывает область
свойств в `/dev/__properties__`, а не файл на диске. Файл читается любым
приложением как обычный файл. Чинится только overlay-модулем, который сам
виден в `/proc/self/mountinfo`. **Конфигурации, в которой железо полностью
скрыто от настойчивого приложения, на этом телефоне не существует.**

## Срочное: override экрана

На устройстве обнаружено:

```
wm size     = Physical size: 720x1600   Override size: 540x1209
wm density  = Physical density: 320     Override density: 240
```

`540×1209 @ 240` — разрешение, которого нет ни у одного серийного телефона.
Это даже не пропорциональное уменьшение панели (0.44665 против 0.45;
пропорционально было бы 540×1200).

Хуже: `wm` подменяет только логический размер. `Display.getMode()`
и `getSupportedModes()` продолжают отдавать физические пиксели —
проверено по `LogicalDisplay.setDisplayInfoOverrideFromWindowManagerLocked`
в AOSP. Приложение видит логический экран 540×1209 на панели 720×1600 и
понимает, что владелец запускал `wm size`.

**Сейчас это самый заметный признак твоего телефона — заметнее модели.**

```sh
wm size reset && wm density reset
```

Модуль **отказывается применять профиль**, пока override активен. Это не
придирка: подмена поверх override — потраченные усилия.

---

## Почему выдуманный профиль хуже стокового

Несогласованный кортеж имеет популяцию **ровно 1**.

Профиль «Pixel 9» на этом телефоне даёт набор: модель `Pixel 9` +
`GL_RENDERER=Mali-G57` + 8 ядер на планировщике Unisoc + 2.72 ГБ +
`low_ram=true` + панель 720×1600 + кодеки `c2.sprd.*`. Такого устройства
не существует и никогда не существовало. Его собственная информация
приближается к полным 32 битам — **подмена сама становится
идентификатором**, причём переживающим переустановку приложений, сброс
рекламного ID и сброс к заводским настройкам.

Честная строка `TECNO KL4` делит толпу со всеми Spark Go 1. Выдуманная не
делит её ни с кем.

Поэтому модуль **жёстко отказывает** профилю, у которого не совпадают
платформа, SoC, число ядер, класс памяти, панель, плотность, `low_ram`,
ABI или версия Android. Это не настройка и не отключается.

## Что можно сделать осмысленно

Толпа существует: `ums9230` — общая платформа Unisoc T606 / T612 / T615 /
T616. Все 12 нм, все 2×A75 + 6×A55, все Mali-G57 MP1.

**Вариант A — другая региональная SKU того же KL4.** Единственный вариант
без единого расхождения по железу: та же плата, тот же чип, та же панель,
тот же Android 14. Прячет региональную партию (`KL4-RU`, `incremental
260414V512`), но не модель. Выигрыш 1–3 бита. Публичных дампов KL4 нет,
значения нужно брать с реального устройства.

**Вариант B — realme Note 50 / Note 60 / C51.** Та же платформа `ums9230`,
тот же Mali-G57, те же 1.8 ГГц (важно: устройства на T606 идут на 1.6 ГГц,
и `cpuinfo_max_freq` это выдаёт), реальная SKU на 3 ГБ, панель 720×1600.
У Note 50 вендорный build ID `TP1A.220624.014` **побайтово совпадает** с
твоим, то есть схема «Android 14 система над Android 13 вендором» выглядит
как настоящая.

Остаточные расхождения, которые останутся при варианте B:
`Build.SOC_MODEL` покажет `T615` против `T612`; `ro.hardware` останется
`ums9230_KL4_go`; ~900 свойств Transsion продолжат называть вендора, а
пространство `ro.oplus.*` у realme будет отсутствовать целиком.

Модуль **не поставляется с профилем**. Причина: одинаковый зашитый профиль
у всех пользователей модуля создаёт когорту «пользователи этого модуля» —
маленькую и коррелирующую с root. Это новый идентификатор, а не меньше
идентификаторов.

## Установка

```sh
# 1. сначала бесплатное
wm size reset && wm density reset

# 2. посмотреть, что стоит сделать
su -c 'sh tools/privacy-actions.sh status'

# 3. собрать модуль
bash tools/build-zip.sh
# приложение Magisk -> Модули -> Установить из хранилища -> dist/coherence-v0.1.0.zip
```

Модуль ставится **инертным**: профиля нет, свойства не изменены.

```sh
spoofctl status            # что видно сейчас
spoofctl check профиль     # проверить, ничего не меняя
spoofctl import профиль    # проверить и принять
spoofctl apply             # применить, дальше перезагрузка
spoofctl revert            # снять
```

Формат профиля: строки `@ключ=значение` описывают железо, которое должно
совпасть с реальным (проверяются, но **не записываются**); остальные
`ключ=значение` — применяемые свойства. `spoofctl --help` печатает полный
шаблон.

## Если телефон не загрузится

Модуль **отключает себя сам** после двух незавершённых загрузок подряд.
Сторож работает в `post-fs-data.sh` и ставит файл `disable` до того, как
Magisk дойдёт до применения свойств на той же загрузке.

Принудительно, без компьютера: держать **Volume Down с самого начала
загрузки, до заставки** — Magisk стартует раньше, чем появляется анимация.

С компьютера:

```sh
adb wait-for-device shell magisk --remove-modules
```

Компьютер должен быть авторизован в adb **заранее**.

Журнал разбора: `/data/adb/coherence/boot.log`.
Снимок исходных свойств: `/data/adb/coherence/baseline.prop`.

## Что модуль не делает и не будет делать

Не обходит Play Integrity, аппаратную аттестацию ключей и антифрод.
Это не исследовалось и не входит в задачу. Аппаратная аттестация сообщает
настоящие manufacturer и model из защищённого хранилища независимо от
любых свойств.

Не ротирует профиль по расписанию. Настоящие телефоны не меняют модель.
Смена свойства на всём устройстве видна каждому SDK в один и тот же момент
при неизменных GAID, SSAID, IP и наборе приложений — это точно
датированное событие, легко склеиваемое между приложениями. Хуже, чем не
трогать ничего.

Не трогает `/data` на загрузке. Сторож умеет откатывать свойства, потому
что они живут в памяти и исчезают при загрузке без модуля. Повреждённый
файл в `/data` он откатить не может: битый `settings_ssaid.xml` роняет
`system_server`, и отключение модуля этот цикл **не чинит**. Поэтому работа
с SSAID вынесена в отдельный инструмент, запускаемый вручную.

## Ещё о том, что остаётся видимым

Наличие root само по себе стоит 6.6–10 бит — больше, чем весь
теоретический выигрыш от подмены `Build.*`.

Набор установленных приложений выдаёт вендора независимо от всего
остального: HiLauncher, Carlcare, Palmstore (`net.bat.store`), клавиатура
HiOS — всё это видно через `resolveActivity()` и
`Settings.Secure.default_input_method` без разрешения `QUERY_ALL_PACKAGES`.
Локаль `ru-RU`, часовой пояс и MCC/MNC оператора сужают толпу сильнее, чем
модель.

Приём OTA-обновления при активном модуле — единственный реалистичный путь
к неисправимому состоянию.

```sh
bash tests/run-all.sh      # 292 проверки, устройство не нужно
bash tools/build-zip.sh    # собрать zip
```

| Файл | Назначение |
|---|---|
| `module/common/fingerprint.sh` | разбор и проверка когерентности fingerprint |
| `module/common/denylist.sh` | запреты по шаблону, разрешения по точному имени |
| `module/post-fs-data.sh` | двухстрайковый сторож (свойства **не** пишет) |
| `module/service.sh` | снимает маркер после `sys.boot_completed` |
| `module/system/bin/spoofctl` | единственный вход для профиля, четыре проверки |
| `tools/collect-device-info.sh` | разведка устройства, только чтение |
| `tools/privacy-actions.sh` | меры с реальной отдачей, вне загрузки |
